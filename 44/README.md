## Размышление 

1.
Контраргумент внедрения избыточности данных:  
Отказываемся от гранулированности того, какие данные каким клиентам выдаем, если в одном вызове сразу получаем всю информацию.

Опровержение:  
Путаются два требования. 

Конфиденциальность информации должна выполняться и при выдаче данных граннулировано и при выдаче всей информации.  
Во втором случае, вся информация может выдаваться только авторизованным для этого клиентам.   
Точно так же как только им выдавалась бы вся информация и с несколькох отдельных вызовов.

А если бы каких-то из прав у них не было, то не выдавалась бы информация и с какого-то из 1-5-7 вызовов.    


2. До последнего не думал о VIEW в БД в контексте избыточности, но укладываются они отлично. 

Именно для избыточности мы их и создаем.

## Вывод

Информационная избыточность делает проще работу, но естественно требует больше передавать по сети от чего может снижаться скорость ответа.  
С другой стороны общее время выполнения задачи может даже снизиться, т.к. вместо 3-5-7 вызовов можно выполнить только один в котором сразу будут все данные, которые будем передавать внутри программы без сетевых вызовов.
